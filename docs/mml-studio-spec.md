# 냥냥 MML 스튜디오 기능·구현 명세서

- 문서 버전: v1.0
- 문서 상태: 구현 결정 완료
- 작성일: 2026-08-02
- 대상 프로젝트: 냥냥 웹앱
- 프로젝트 파일 확장자: `.nyangmml`
- 관련 문서: `keyboard-app-product-spec.md`

이 문서는 기존 건반 앱 명세에 MML 스튜디오 기능을 추가하는 확장 명세다. 기존 문서의 `연주 녹음 및 재생`, `메트로놈` 제외 규정은 일반 건반 화면의 독립 기능에 관한 과거 범위로 보고, MML 화면 안의 녹음·재생·메트로놈에는 이 문서가 우선한다.

## 1. 목적

냥냥에 MML 편집, 재생, 건반 연주 기록, 피아노롤 확인 기능을 추가한다.

사용자는 기존 발바닥 건반을 연주하면서 다음 작업을 할 수 있어야 한다.

1. MML 텍스트를 트랙별로 작성하거나 붙여넣는다.
2. MML을 현재 냥냥 음색으로 재생한다.
3. 터치, 마우스, 컴퓨터 키보드 연주를 음 길이에 맞춰 MML로 기록한다.
4. 화음을 사용자가 연결한 여러 트랙에 자동 분배한다.
5. 피아노롤에서 재생 위치와 음 길이를 확인하고 해당 MML 문자열로 이동한다.
6. 일반 MML과 냥냥 전용 프로젝트 파일을 저장하고 다시 불러온다.

이 기능은 마이크 녹음이 아니다. 앱이 이미 계산한 건반 음높이와 입력 시각만 기록한다.

## 2. 기본 원칙

1. MML 기능을 사용하지 않을 때 기존 건반의 반응 속도와 동작이 달라지지 않아야 한다.
2. 화면은 기존과 동일하게 가로형 레이아웃만 사용한다.
3. 트랙 수와 MML 글자 수를 냥냥에서 제한하지 않는다.
4. 붙여넣은 MML 원문은 사용자가 요청하기 전까지 임의로 정리하거나 압축하지 않는다.
5. 녹음 이벤트는 먼저 원본 상태로 보존하고, 보정 설정을 바꿀 때마다 원본에서 다시 계산한다.
6. 여러 건반에서 동시에 들어온 음은 건반 세트별로 따로 처리하지 않고 같은 시점의 하나의 화음으로 함께 계산한다.
7. 서버와 사용자 계정을 사용하지 않으며 프로젝트와 자동 저장은 기기 안에서 처리한다.

## 3. MML 화면 진입과 전체 배치

### 3.1 MML 버튼

- 왼쪽 상단의 기존 고양이 발바닥 마크를 MML 열기·닫기 버튼으로 사용한다.
- 별도의 긴 설명 문구는 표시하지 않는다.
- MML이 닫혀 있을 때 버튼을 누르면 분할 화면을 연다.
- MML이 열려 있을 때 같은 버튼을 누르면 기존 전체 건반 화면으로 돌아간다.

### 3.2 불어서 연주와의 충돌

MML은 `불어서 연주` 기능을 지원하지 않는다.

- 불어서 연주가 꺼져 있으면 바로 MML 화면을 연다.
- 불어서 연주가 켜진 상태에서 MML 버튼을 누르면 확인창을 표시한다.

```text
불어서 연주를 끄고 MML을 열까요?
[취소] [끄고 열기]
```

- `취소`를 누르면 MML을 열지 않고 불어서 연주 상태를 유지한다.
- `끄고 열기`를 누르면 불어서 연주를 끈 뒤 MML을 연다.

### 3.3 분할 화면

MML을 열면 전체 스테이지를 좌우 절반으로 나눈다.

```text
┌────────────────────────────┬────────────────────────────┐
│ MML 편집·녹음 영역         │ 기존 건반 연주 영역         │
│                            │                            │
│ 녹음·재생 상태             │ 옥타브·전조                 │
│ 트랙 목록                  │ 고양이 또는 여유 공간       │
│ 피아노롤                   │ 발바닥 건반                 │
│ 선택 트랙 MML 편집칸       │                            │
└────────────────────────────┴────────────────────────────┘
```

- 왼쪽 절반에는 MML 기능을 표시한다.
- 오른쪽 절반에는 기존 옥타브, 전조, 고양이, 발바닥 건반을 크기에 맞게 재배치한다.
- 한 건반과 두 건반 표시를 모두 지원한다.
- 공간이 충분하면 고양이를 계속 표시한다.
- 모바일 또는 두 건반 표시로 공간이 부족하면 고양이를 자동으로 숨긴다.
- 고양이를 숨겨도 연주, 녹음, 재생에는 영향을 주지 않는다.
- 공간 부족 여부는 기기 이름이 아니라 실제 컨테이너 크기로 판단한다.

## 4. 설정 화면 개편

기존 설정창을 다음 두 개의 상위 탭으로 나눈다.

1. `건반 설정`
2. `MML 설정`

### 4.1 건반 설정

현재 제공하는 다음 설정을 유지한다.

- 건반 한 세트 또는 두 세트
- 왼쪽·오른쪽 옥타브 프리셋
- 낮은 B와 높은 C 표시
- 음 이름과 임시표 표기
- 키 매핑 문자
- 음색과 전체 음량
- 불어서 연주
- 건반·옥타브·전조 단축키

### 4.2 MML 설정

다음 항목을 관리한다.

- 실시간 녹음 또는 이어붙이기 녹음
- 수정 모드 또는 삽입 모드
- 왼쪽·오른쪽 건반의 연결 트랙
- 높은 음 우선 또는 낮은 음 우선
- 박자 보정 단위
- 자동 리듬 인식
- 카운트인 길이
- 메트로놈 켜기와 음량
- 삽입 시 전체 트랙 또는 실제 사용 트랙 밀기
- 트랙별 기본 기록 `v`
- MML 단축키
- 이어붙이기 쉼표 키

트랙 연결처럼 녹음 중 자주 확인하는 값은 MML 화면에도 요약해서 표시하고, 설정창을 열지 않고 빠르게 바꿀 수 있게 한다.

## 5. 트랙 모델

### 5.1 트랙 생성과 삭제

- 새 프로젝트는 기본 3트랙으로 시작한다.
- 기본 이름은 `Track 1`, `Track 2`, `Track 3`이다.
- 트랙은 필요한 만큼 추가할 수 있다.
- 트랙 수는 3개 미만으로도 줄일 수 있다.
- 트랙 이름은 한글, 영문, 숫자를 포함해 자유롭게 바꿀 수 있다.
- 트랙 색상도 자유롭게 변경할 수 있다.
- 화면에 표시하는 이름과 별개로 각 트랙은 변경되지 않는 고유 ID로 구분한다.

### 5.2 트랙별 상태

```ts
type MmlTrack = {
  id: string;
  name: string;
  color: string;
  sourceText: string;
  themeId: string;
  mixerVolume: number;
  recordVelocity: number;
  muted: boolean;
  solo: boolean;
  pianoRollVisible: boolean;
};
```

- `mixerVolume`은 MML의 `v`와 별도의 냥냥 재생 음량이다.
- 실제 출력 음량은 `전체 음량 × 트랙 음량 × MML v`로 계산한다.
- 새 트랙의 기본 기록 음량은 `v15`이다.
- `음소거`는 해당 트랙의 재생만 끈다.
- 하나 이상의 트랙이 `혼자 듣기`이면 혼자 듣기로 선택된 트랙만 재생한다.
- `피아노롤 숨김`은 표시만 끄며 재생에는 영향을 주지 않는다.

### 5.3 트랙별 음색

- 트랙마다 냥 보이스, 포근 신스 등 등록된 음색을 별도로 선택할 수 있다.
- 새 트랙은 생성 순간에 건반에서 선택된 현재 음색을 복사한다.
- 이후 건반 음색을 바꿔도 이미 생성된 트랙 음색은 바뀌지 않는다.
- 녹음 중 직접 누르는 소리는 현재 건반 음색으로 낸다.
- 녹음 결과를 MML로 재생할 때는 각 트랙의 음색을 사용한다.
- 서로 다른 트랙 음색이 동시에 재생될 때 고양이 이미지는 현재 선택한 트랙의 음색을 사용한다.
- 피아노롤 음표는 트랙 색상으로 구분한다.

## 6. 건반과 녹음 트랙 연결

### 6.1 기본 연결

- 왼쪽 건반: `Track 1`, `Track 2`
- 오른쪽 건반: `Track 3`
- 기본 음높이 배정: 높은 음부터 낮은 번호 트랙

### 6.2 사용자 설정

- 왼쪽 건반과 오른쪽 건반에 각각 트랙을 여러 개 연결할 수 있다.
- 같은 트랙을 왼쪽과 오른쪽에 동시에 연결할 수 있다.
- 트랙 순서는 사용자가 정하며 낮은 순서가 우선 배정 위치가 된다.
- 음높이 배정은 `높은 음 우선`과 `낮은 음 우선` 중 선택할 수 있다.

### 6.3 양쪽 건반 통합 배정

화음 배정은 왼쪽과 오른쪽을 분리해서 계산하지 않는다.

예:

```text
왼쪽 연결: Track 1, Track 2
오른쪽 연결: Track 1, Track 2
우선순위: 높은 음 우선
입력: 왼쪽 C + 오른쪽 E

결과:
Track 1 = E
Track 2 = C
```

양쪽을 합친 동시 입력이 두 트랙 용량을 넘으면 초과 음은 소리만 나고 MML에는 기록하지 않는다. 이때 놓친 음과 시점을 포함한 경고를 표시한다.

### 6.4 최대 보존 우선

일부 트랙만 공유할 때는 음높이 순서보다 기록 가능한 음의 개수를 먼저 최대화한다.

예:

```text
왼쪽 C가 사용할 수 있는 트랙: Track 1
오른쪽 E가 사용할 수 있는 트랙: Track 1, Track 2

결과:
Track 1 = C
Track 2 = E
```

높은 음 우선이라도 E를 Track 1에 넣어서 C를 버리지 않는다. 가능한 음을 모두 보존하는 배정 중에서만 높은 음 또는 낮은 음 우선순위를 적용한다.

### 6.5 시간차가 있는 화음

트랙은 건반을 누르는 순간에 최종 확정하지 않는다. 원본 입력을 먼저 기록하고 음이 끝난 뒤 겹친 시간과 음높이를 계산한다.

예:

```text
C를 2박 유지
1박 뒤 E를 1박 입력
Track 1, Track 2 연결
높은 음 우선

Track 1: r4e4
Track 2: c2
```

C가 먼저 눌렸더라도 나중에 들어온 높은 E를 Track 1에 배정하고 C를 Track 2에 배정한다. 하나의 음은 시작부터 끝까지 같은 트랙을 유지한다.

## 7. MML 문법

### 7.1 호환 기준

마비노기 계열 MML과 사용자가 제공한 기준 코드를 재생할 수 있어야 한다. 다음 자료는 동작과 테스트 참고용으로 사용한다.

- `fourthline/mmlTools`: https://github.com/fourthline/mmlTools
- 마비노기 모바일 작곡 안내: https://mabinogimobile.nexon.com/Info/Guide/2751071

`mmlTools`의 GPL 코드를 냥냥 코드에 복사하지 않는다. 문법 동작과 공개된 테스트 사례를 참고해 TypeScript로 독립 구현한다.

### 7.2 전체 형식

```text
MML@트랙1,트랙2,트랙3;
```

- `MML@`로 시작하고 `;`로 끝나는 결합 형식을 지원한다.
- 쉼표로 트랙을 구분한다.
- 트랙별 편집칸에는 해당 트랙 내용만 표시한다.
- 전체 복사와 `.mml` 저장 시 자동으로 결합한다.
- 결합된 텍스트를 붙여넣으면 자동으로 트랙을 나눈다.
- 트랙 수와 글자 수는 제한하지 않는다.

### 7.3 지원 토큰

| 토큰 | 의미 |
| --- | --- |
| `a b c d e f g` | 현재 옥타브의 음표 |
| `r` | 쉼표 |
| `n숫자` | 절대 음 번호 |
| `+`, `#`, `-` | 반음 올림과 내림 |
| `l숫자` | 기본 음 길이 |
| `o숫자` | 옥타브 지정 |
| `<`, `>` | 옥타브 이동 |
| `t숫자` | 전체 곡 템포 변경 |
| `v숫자` | MML 음량 |
| `.` | 점음표 |
| `&` | 같은 음 연결 |
| `,` | 트랙 구분 |

- 대소문자를 구분하지 않는다.
- `n61`처럼 길이를 따로 적지 않은 절대 음은 현재 `l` 값을 사용한다.
- 사용자가 제공한 `l6`, `a12`, `r3`, `a3&a4` 등의 길이를 해석한다.
- 붙여넣은 원문의 공백과 줄바꿈은 프로젝트 안에서 보존한다.

### 7.4 주석

다음 주석을 지원한다.

```text
// 한 줄 주석
/* 여러 줄
   주석 */
```

- 파싱과 재생에서는 주석을 제외한다.
- `.nyangmml` 프로젝트에는 주석을 보존한다.
- 일반 `.mml` 저장과 MML 클립보드 복사에서는 모든 주석을 제거한다.

### 7.5 원문 유지와 코드 정리

- 붙여넣거나 직접 입력한 MML을 자동으로 다시 작성하지 않는다.
- 텍스트 편집, 공백, 줄바꿈, 명령 순서를 최대한 보존한다.
- 사용자가 `코드 정리` 버튼을 눌렀을 때만 `l`, `o`, 쉼표, 연결음 등을 이용해 정리·압축한다.
- 코드 정리 전에는 변경 결과 미리보기를 제공한다.
- 실행 취소로 정리 이전 원문으로 돌아갈 수 있어야 한다.

### 7.6 호환성 검사

- 평소에는 호환 범위, 글자 수, 트랙 제한을 표시하지 않는다.
- 별도의 `호환성 검사` 버튼을 눌렀을 때만 결과를 보여준다.
- 검사는 마비노기에 옮길 때 문제가 될 수 있는 항목을 참고 정보로 표시한다.
- 검사 결과가 있어도 냥냥의 편집, 재생, 저장을 막지 않는다.

## 8. 박자와 시간 모델

### 8.1 내부 해상도

- 4분음표당 96 tick을 사용한다.
- 온음표는 384 tick이다.
- MML 음 길이 계산은 마비노기 계열 동작과 맞춘다.
- 녹음 원본은 tick 변환 전의 오디오 시각도 함께 보관한다.

### 8.2 박자표

- 기본 박자표 선택지를 제공한다.
- 예: `2/4`, `3/4`, `4/4`, `6/8`, `9/8`, `12/8`.
- 기본값은 `4/4`이다.
- 분자와 분모는 양의 정수로 자유롭게 직접 입력할 수 있다.
- `18/8`, `7/12` 같은 박자표도 허용한다.
- 곡 중간에 박자표를 변경할 수 있다.
- 박자표는 MML 표준 토큰이 아니므로 `.nyangmml` 프로젝트 메타데이터에 저장한다.
- 일반 `.mml`로 내보내면 음과 템포는 유지하지만 박자표 정보는 제외된다.

### 8.3 템포

- MML의 `t` 명령으로 곡 중간 템포 변경을 지원한다.
- 템포는 트랙별 효과가 아니라 전체 곡의 전역 시간선에 적용한다.
- 여러 트랙에 있는 `t` 명령을 절대 tick 위치 기준으로 하나의 템포 맵으로 합친다.
- 같은 tick에 서로 다른 `t` 값이 있으면 자동 선택하지 않고 오류로 표시한다.
- 충돌이 해결되기 전에는 재생하지 않는다.

### 8.4 피아노롤 시간선 메뉴

- 피아노롤의 시간 눈금 또는 빈 위치를 누르면 현재 위치를 옮긴다.
- 우클릭으로 위치 메뉴를 연다.
- 터치 환경에서는 길게 누르기로 같은 메뉴를 연다.
- 메뉴에서 다음 작업을 제공한다.
  - 해당 위치부터 박자표 변경
  - 해당 위치에 템포 명령 추가·수정·삭제
  - 녹음 시작 위치 지정
- 템포 추가는 현재 선택한 트랙의 해당 MML 위치에 `t값`을 삽입한다.
- 박자표 변경은 프로젝트 메타데이터에 기록한다.

## 9. 피아노롤

### 9.1 역할

피아노롤은 음표를 직접 이동하거나 크기를 바꾸는 편집기가 아니다. 재생 위치, 음높이, 음 길이를 확인하고 MML 텍스트의 정확한 위치로 이동하기 위한 화면이다.

### 9.2 표시 요소

- 가로축: 마디, 박, 세부 박자선
- 세로축: 피아노 음높이와 옥타브
- 음표: 실제 길이에 맞춘 가로 막대
- 재생 위치: 움직이는 세로선
- 녹음 위치와 반복 범위
- 템포와 박자표 변경 표시
- 트랙별 색상

### 9.3 트랙 표시

- 선택한 트랙은 진한 색으로 표시한다.
- 선택하지 않은 트랙은 흐리게 함께 표시한다.
- 트랙별 `피아노롤 숨김`을 켜면 해당 트랙만 감춘다.
- 음소거와 숨김은 서로 독립적이다.

### 9.4 MML 텍스트 이동

- 피아노롤의 음표를 누르면 해당 트랙을 선택한다.
- 해당 음표를 만든 MML 문자열로 편집칸을 스크롤한다.
- 음표 토큰을 선택 상태로 만든다.
- `c4&c8`처럼 여러 토큰이 한 음을 구성하면 연결된 전체 범위를 선택한다.
- 빈 위치를 누르면 선택 트랙에서 해당 시간에 대응하는 음표 또는 쉼표 앞의 편집 위치로 이동한다.
- 피아노롤에서 음표를 생성, 삭제, 이동, 길이 변경하지 않는다.

### 9.5 재생과 반복

- 재생 중에는 현재 위치선이 움직인다.
- 화면 밖으로 나가면 자동 스크롤한다.
- 사용자가 스크롤을 직접 조작하면 잠시 자동 추적을 멈출 수 있다.
- 전체 곡 반복을 지원한다.
- 시간 눈금에서 시작과 끝을 드래그해 부분 반복 구간을 지정할 수 있다.
- 반복 경계에서 이전 음을 정리한 뒤 정확한 위치에서 다시 시작한다.

## 10. 녹음 모드

### 10.1 공통 녹음 입력

다음 입력을 모두 기록한다.

- 터치와 멀티터치
- 마우스와 포인터 글리산도
- 컴퓨터 키보드 매핑
- 왼쪽과 오른쪽 건반
- 녹음 중 변경된 옥타브와 전조가 반영된 실제 출력 MIDI 음높이

MML 자동 재생이 만든 음은 다시 녹음하지 않는다.

### 10.2 실시간 녹음

- 기본 녹음 모드이다.
- 메트로놈과 같은 BPM 시간선에 맞춰 녹음한다.
- 녹음 시작 뒤 시간은 계속 흐른다.
- 연주하지 않은 구간은 쉼표로 기록한다.
- 메트로놈 소리를 꺼도 내부 시간선은 계속 진행한다.
- 기존 곡 중간에서 녹음하면 선택한 재생 위치에서 시작한다.

### 10.3 이어붙이기 녹음

- 음 또는 쉼표 입력이 있을 때만 기록 시간이 흐른다.
- 아무 입력 없이 기다린 시간은 기록하지 않는다.
- 모든 음을 뗀 순간 기록 시간선이 멈춘다.
- 하나 이상의 음을 누르고 있는 동안 기록 시간선이 계속 흐른다.
- 다음 음을 나중에 눌러도 앞 음 또는 쉼표 바로 뒤에 이어 붙는다.

예:

```text
C를 2박 입력
D를 1박 입력
잠시 대기
E를 1박 입력

결과: c2d4e4
대기 시간의 쉼표는 없음
```

### 10.4 이어붙이기 쉼표

- 기본 쉼표 입력 키는 `S`이다.
- 설정에서 변경할 수 있다.
- 쉼표 키를 누른 길이를 BPM과 보정 설정에 맞춰 쉼표로 기록한다.
- 예: `S`를 2박 누르면 `r2`를 기록한다.
- 쉼표 입력은 현재 녹음에 연결된 모든 트랙의 위치를 함께 이동한다.
- 한 트랙에 음이 있고 다른 연결 트랙에 음이 없으면 다른 트랙에는 같은 시간만큼 쉼표가 자동으로 생긴다.

### 10.5 이어붙이기 모드의 메트로놈

- 메트로놈 소리를 자유롭게 켜고 끌 수 있다.
- 메트로놈 소리는 녹음 시간 진행 여부와 독립적이다.
- 메트로놈이 울려도 음이나 쉼표를 입력하지 않으면 기록 시간은 흐르지 않는다.
- 이어붙이기 모드에서 메트로놈은 길이 입력을 돕는 안내이며 실시간 녹음 시간선을 만들지 않는다.

## 11. 메트로놈과 카운트인

- 카운트인 선택: `없음`, `1마디`, `2마디`.
- 기본값은 `1마디`이다.
- 카운트인 중 직접 연주한 음은 소리는 낼 수 있지만 녹음에는 넣지 않는다.
- 첫 박은 높은 클릭, 나머지 박은 낮은 클릭으로 구분한다.
- 메트로놈은 선택한 음색과 리버브를 사용하지 않는 짧은 전용 클릭음을 사용한다.
- 메트로놈 음량은 MML 설정에서 별도로 조절한다.
- 실시간 녹음에서는 메트로놈의 소리 여부와 관계없이 BPM에 맞춘 같은 시계를 사용한다.

## 12. 박자 보정과 자동 리듬 인식

### 12.1 보정 선택

- `1/1`
- `1/2`
- `1/4`
- `1/8`
- `1/16`
- `1/32`
- `보정 안 함`

기본값은 `1/8`이다.

### 12.2 원본 보존

각 음의 누른 시각과 뗀 시각을 원본 초 단위로 보존한다. 사용자가 보정 단위를 바꾸면 이미 보정된 결과를 다시 보정하지 않고 원본에서 새로 계산한다.

### 12.3 일반 보정

1. 녹음 시작점을 기준으로 입력 시각을 tick으로 변환한다.
2. 시작과 종료를 선택한 보정 격자에 맞춘다.
3. 보정 뒤 길이가 0이면 최소 한 격자 길이를 부여한다.
4. 녹음 끝의 빈 시간은 추가하지 않는다.
5. 최종 프로젝트 길이는 마지막 음 또는 명시적으로 입력한 쉼표가 끝난 위치이다.

### 12.4 자동 리듬 인식

자동 리듬 인식은 일반 리듬과 셋잇단을 별도 모드로 나누지 않는다. 한 연주 안에서 다음 후보를 함께 비교한다.

- 일반 2분할과 4분할 계열
- 점음표
- 셋잇단 계열
- 연결음으로 표현해야 하는 복합 길이

원본 입력의 시작 간격과 길이가 가장 가까운 조합을 선택한다. 예를 들어 한 박 안에 거의 같은 간격의 세 음이 있으면 셋잇단 후보를 우선한다. 판정이 애매하면 해당 음을 표시하고 사용자가 MML 텍스트에서 수정할 수 있게 한다.

## 13. 서스테인 기록

- 서스테인 상태를 MML에 기록하지 않는다.
- 음 길이는 건반을 실제로 누른 시점부터 뗀 시점까지만 사용한다.
- 녹음 중 서스테인은 사용자가 듣는 실제 건반 소리에는 적용할 수 있다.
- 서스테인을 뗀 시점까지 음 길이를 늘리지 않는다.
- MML 자동 재생 중 스페이스바 서스테인은 예약된 MML 음 길이를 변경하지 않는다.

## 14. 수정 모드와 삽입 모드

### 14.1 수정 모드

- 기본 편집 방식이다.
- 현재 재생 위치에서 녹음을 시작한다.
- 새 연주가 실제로 배정된 트랙만 녹음 시작부터 마지막 입력 종료까지 덮어쓴다.
- 건반에 연결됐지만 새 음이 배정되지 않은 트랙의 기존 내용은 유지한다.
- 예: Track 1·2가 연결돼 있고 새 음이 Track 1에만 배정되면 Track 2는 덮어쓰지 않는다.
- 녹음 중 덮어쓸 대상 트랙은 해당 구간에서 음소거한다.
- 나머지 트랙은 반주로 재생한다.

### 14.2 삽입 모드

- 현재 재생 위치에 새 시간을 삽입한다.
- 기본값은 `전체 트랙 밀기`이다.
- 설정에서 `실제로 사용한 트랙만 밀기`를 선택할 수 있다.
- 삽입 위치 이후의 기존 내용은 녹음 중 재생하지 않는다.
- 녹음이 끝나면 마지막 입력 종료까지의 길이만큼 설정된 트랙 범위를 뒤로 이동한다.
- 녹음 끝 뒤의 빈 대기 시간은 삽입 길이에 포함하지 않는다.

## 15. 녹음 이벤트와 트랙 배정 구현

### 15.1 원본 이벤트

```ts
type RecordedInput = {
  id: string;
  side: "left" | "right";
  inputId: string;
  soundingMidi: number;
  startedAtAudioTime: number;
  endedAtAudioTime: number;
  releaseKind: "key-up" | "pointer-up" | "cancel" | "record-stop";
};
```

### 15.2 배정 순서

1. 원본 입력을 초 단위로 수집한다.
2. 선택한 보정과 자동 리듬 인식을 적용한다.
3. 시간상 겹치는 음을 하나의 겹침 그래프로 구성한다.
4. 각 음이 사용할 수 있는 트랙을 입력 건반의 연결 설정에서 구한다.
5. 기록 가능한 음의 개수를 최대화하는 배정을 찾는다.
6. 최대 보존 결과가 여러 개면 높은 음 또는 낮은 음 우선순위를 적용한다.
7. 같은 조건이면 사용자가 지정한 트랙 순서를 적용한다.
8. 배정되지 못한 음은 기록하지 않고 경고 목록에 넣는다.

음이 시작된 뒤 더 높은 음이 들어오더라도 전체 겹침 구간 계산 결과에 따라 앞 음의 트랙을 바꿀 수 있다. 오디오 재생 자체는 녹음 당시 건반 음색으로 계속 정상 출력한다.

## 16. MML 생성

### 16.1 기본 출력

- 새로 기록한 트랙의 첫 음량은 기본 `v15`를 사용한다.
- 같은 길이가 반복되면 `l`을 사용할 수 있다.
- 옥타브 이동은 `o`, `<`, `>` 중 읽기 쉬운 표현을 선택한다.
- 점음표로 정확히 표현할 수 있으면 점음표를 사용한다.
- 한 토큰으로 표현하기 어려운 길이는 `&`로 연결한다.
- 트랙 시작 전의 빈 시간과 음 사이의 빈 시간은 `r`로 만든다.
- 화음은 여러 MML 트랙으로 출력한다.

### 16.2 원문 부분 수정

- 수정·삽입 녹음은 영향을 받는 트랙과 시간 범위만 다시 생성한다.
- 영향을 받지 않는 앞뒤 원문을 가능한 한 유지한다.
- 사용자가 작성한 주석은 영향 범위 밖에서 유지한다.
- 코드 재생성 결과는 하나의 실행 취소 단위로 기록한다.

## 17. 재생 엔진

### 17.1 공통 MIDI 재생 함수

현재 화면 건반에 묶인 음 시작 함수를 MIDI 기반 공통 함수로 분리한다.

```ts
playMidiNote({ sourceId, midi, velocity, themeId, mixerGain, visualKeyId? })
releaseMidiNote(sourceId, releaseMode)
```

- 직접 건반은 옥타브와 전조를 계산한 뒤 호출한다.
- MML은 파싱된 절대 MIDI 음으로 호출한다.
- 음원 샘플 속도, 합성음, 전체 음량, 종료 처리는 기존 오디오 엔진을 공유한다.
- 입력 출처별 `sourceId`를 사용해 MML 정지 시 직접 누른 건반 음을 끄지 않는다.

### 17.2 예약 방식

- `AudioContext.currentTime`을 기준 시계로 사용한다.
- 짧은 간격으로 앞으로 일정 구간을 미리 예약한다.
- 모든 곡을 한 번에 타이머로 등록하지 않는다.
- 템포 변경 지점을 지나면 다음 이벤트의 실제 시각을 새 템포로 계산한다.
- 정지, 일시정지, 반복 경계에서 예약된 MML 음을 안전하게 취소한다.

### 17.3 재생 중 직접 연주

- MML 재생 중에도 오른쪽 건반 영역을 직접 연주할 수 있다.
- 직접 연주 음은 현재 건반 음색을 사용한다.
- MML 음은 트랙별 음색을 사용한다.
- 녹음 상태가 아니면 직접 연주를 MML에 추가하지 않는다.

- 실행 취소·다시 실행
- 전체 MML 복사
- 파일 저장·불러오기

### 18.2 기본 단축키

| 기능 | 기본값 |
| --- | --- |
| MML 열기·닫기 | `Alt+M` |
| 재생·일시정지 | `Alt+P` |
| 녹음 시작·종료 | `Alt+R` |
| 정지 | `Alt+S` |
| 이어붙이기 쉼표 | `S` |
| 실행 취소 | `Ctrl/Cmd+Z` |
| 다시 실행 | `Ctrl/Cmd+Shift+Z` |

- MML 단축키는 설정에서 모두 변경할 수 있다.
- 텍스트 편집칸에 포커스가 있을 때는 연주·녹음 단축키를 실행하지 않는다.
- 실행 취소와 다시 실행은 텍스트 편집의 표준 동작을 우선한다.
- 단축키가 기존 건반, 옥타브, 전조 단축키와 충돌하면 저장 전에 알려준다.

## 19. 오류 처리

### 19.1 MML 문법 오류

- 트랙, 줄, 글자 위치와 원인을 표시한다.
- 오류가 있으면 해당 프로젝트의 MML 재생을 막는다.
- 정상으로 해석된 마지막 피아노롤을 흐리게 유지한다.
- 원문은 지우거나 자동 수정하지 않는다.
- 오류를 고치면 즉시 다시 파싱하고 피아노롤을 갱신한다.

### 19.2 화음 용량 초과

- 연결된 트랙보다 동시에 입력된 음이 많으면 초과 음은 녹음하지 않는다.
- 직접 연주 소리는 계속 낸다.
- 녹음 상태 영역에 놓친 음의 개수와 시점을 표시한다.
- 같은 녹음 중 반복 경고가 화면을 가리지 않도록 합쳐서 표시한다.

### 19.3 입력 취소

- 포인터 취소, 포커스 손실, 페이지 숨김, 녹음 강제 종료 시 활성 음을 정리한다.
- 녹음 중이던 음은 취소 시각 또는 녹음 종료 시각까지의 유효한 이벤트로 닫는다.
- 페이지 숨김 시 MML 재생은 일시정지한다.

## 20. 실행 취소와 다시 실행

- MML 텍스트 입력은 짧은 연속 입력을 하나의 실행 취소 단위로 묶는다.
- 녹음 한 번, 코드 정리 한 번, 트랙 추가·삭제, 설정 변경을 각각 의미 있는 단위로 기록한다.
- 트랙 삭제를 취소하면 MML, 이름, 색상, 음색과 믹서 설정을 모두 복원한다.
- 마지막 자동 저장 프로젝트에는 편집 기록도 저장한다.
- 브라우저를 다시 열어도 마지막 프로젝트의 실행 취소를 이어갈 수 있다.
- `.nyangmml` 파일에는 실행 취소 기록을 넣지 않는다.
- `.nyangmml`을 불러오면 그 상태를 시작점으로 새 실행 취소 기록을 만든다.

## 21. 저장과 불러오기

### 21.1 자동 저장

- 마지막 작업 프로젝트 하나만 브라우저에 자동 저장한다.
- 트랙, 원문, 프로젝트 설정, 실행 취소 기록을 복원한다.
- 여러 자동 저장 프로젝트 목록은 만들지 않는다.
- 사용자가 장기 백업하려면 `.nyangmml` 파일을 직접 저장한다.
- 큰 프로젝트와 편집 기록을 안전하게 저장하기 위해 IndexedDB를 사용한다.

### 21.2 `.mml`

- MML 텍스트만 저장한다.
- `MML@트랙1,트랙2,...;` 형식으로 결합한다.
- 주석을 제거한다.
- 트랙 이름, 색상, 음색, 믹서, 건반 연결, 박자표를 포함하지 않는다.
- 글자 수와 트랙 수 때문에 저장을 막지 않는다.

### 21.3 `.nyangmml`

JSON 기반의 버전 있는 프로젝트 형식을 사용한다.

```json
{
  "format": "nyangmml",
  "version": 1,
  "title": "프로젝트 제목",
  "tracks": [],
  "tempoMap": [],
  "timeSignatureMap": [],
  "keyboardRouting": {},
  "recordingSettings": {},
  "viewSettings": {}
}
```

포함 항목:

- 프로젝트 제목
- 트랙별 MML 원문과 주석
- 트랙 이름과 색상
- 트랙별 음색, 음량, 음소거, 혼자 듣기, 숨김
- 왼쪽·오른쪽 건반 연결
- 음높이 우선순위
- 템포와 박자표 변경 위치
- 녹음, 보정, 메트로놈 설정
- 반복 구간과 피아노롤 보기 설정

제외 항목:

- 실행 취소와 다시 실행 기록
- 현재 눌린 음
- 현재 오디오 노드
- 마이크 데이터

### 21.4 프로젝트 이름

- 프로젝트 제목을 자유롭게 입력할 수 있다.
- 기본 파일명은 `프로젝트제목.nyangmml`이다.
- 제목이 없으면 저장 시점의 날짜와 시간을 파일명으로 사용한다.
- 파일명에 사용할 수 없는 문자는 안전한 문자로 바꾼다.

### 21.5 불러오기 방식

`.mml` 또는 붙여넣은 MML을 다음 방식으로 불러올 수 있다.

1. 현재 프로젝트 전체 교체
2. 기존 곡 뒤에 이어 붙이기
3. 새 트랙으로 추가
4. 선택한 트랙만 교체

`.nyangmml` 파일은 프로젝트 전체를 복원한다. 불러오기 전에 저장하지 않은 현재 작업이 있으면 확인한다.

### 22.1 핵심 분리

- 오디오 엔진은 MIDI 음을 재생하고 입력 출처별로 종료한다.
- 입력 이벤트 계층은 터치, 키보드, MML 재생을 공통 형식으로 전달한다.
- 녹음기는 직접 입력만 수집한다.
- 파서는 MML 원문과 피아노롤 이벤트 사이의 위치 매핑을 만든다.
- 소스 맵은 피아노롤 음표 클릭을 정확한 텍스트 범위로 연결한다.
- 플레이어는 파싱된 이벤트와 전역 템포 맵을 예약한다.
- 프로젝트 저장과 자동 저장은 별도 버전 관리 계층에서 처리한다.

## 23. 구현 순서

기능을 축소해서 별도 출시하는 단계가 아니라, 완성 기능을 기존 앱을 깨뜨리지 않고 조립하기 위한 작업 순서다.

1. 기존 오디오 시작·종료를 MIDI 기반 공통 엔진으로 분리한다.
2. 기존 터치, 멀티터치, 마우스, 키보드, 서스테인 회귀 테스트를 통과시킨다.
3. 마비노기 MML 토크나이저, 파서, 템포 맵과 소스 맵을 구현한다.
4. 사용자 제공 MML을 고정 호환성 테스트로 추가한다.
5. 트랙별 음색과 믹서를 지원하는 예약 재생기를 구현한다.
6. 분할 화면, 트랙 목록, 텍스트 편집기와 피아노롤을 구현한다.
7. 재생, 일시정지, 정지, 전체·구간 반복을 연결한다.
8. 원본 입력 녹음과 실시간·이어붙이기 시간선을 구현한다.
9. 자동 리듬 인식, 보정, 화음 트랙 배정을 구현한다.
10. 수정·삽입 녹음과 기존 트랙 반주 동작을 구현한다.
11. `.mml`, `.nyangmml`, 붙여넣기와 네 가지 가져오기 방식을 구현한다.
12. 자동 저장과 실행 취소 기록을 구현한다.
13. 설정 탭, 단축키, 오류와 녹음 경고를 완성한다.
14. 데스크톱과 모바일 가로형 레이아웃을 검증한다.
15. 개인정보처리방침에 기기 내부 MML 자동 저장 내용을 반영한다.

## 24. 테스트 요구사항

### 24.1 MML 파서

- 사용자 제공 `MML@...;` 기준 코드가 오류 없이 3트랙으로 분리된다.
- `a–g`, `r`, `n`, `l`, `o`, `t`, `v`, `<`, `>`, `.`, `&`, 임시표를 해석한다.
- `l6`, `a12`, `r3`, `a3&a4`를 정확한 tick으로 변환한다.
- 피아노롤 이벤트가 원문의 정확한 글자 범위를 가진다.
- 같은 tick의 서로 다른 템포를 오류로 표시한다.
- 주석이 재생에 영향을 주지 않고 `.mml` 출력에서 제거된다.

### 24.2 녹음과 화음

- 왼쪽과 오른쪽 입력을 합친 뒤 트랙을 배정한다.
- 같은 트랙을 양쪽에 연결할 수 있다.
- 가능한 음의 수를 최대화한 뒤 음높이 우선순위를 적용한다.
- C가 먼저 시작하고 E가 나중에 겹치는 예제가 `r4e4`와 `c2`로 배정된다.
- 트랙 용량을 넘은 음은 기록하지 않고 경고한다.
- 서스테인은 MML 길이를 늘리지 않는다.

### 24.3 녹음 시간

- 실시간 녹음의 무음 구간은 쉼표가 된다.
- 이어붙이기 녹음의 대기 시간은 무시된다.
- 하나 이상의 음이 눌린 동안만 이어붙이기 시간이 흐른다.
- 쉼표 키가 모든 연결 트랙을 같은 길이만큼 이동시킨다.
- 마지막 입력 이후의 대기 시간은 프로젝트 길이에 포함되지 않는다.
- 일반 리듬과 셋잇단을 한 연주 안에서 함께 판정한다.

### 24.4 수정과 삽입

- 수정 모드에서 실제 사용된 트랙만 덮어쓴다.
- 사용되지 않은 연결 트랙의 기존 내용이 유지된다.
- 덮어쓰기 대상 트랙은 녹음 중 음소거되고 다른 트랙은 반주한다.
- 삽입 모드 기본값은 전체 트랙 밀기다.
- 실제 사용 트랙만 밀기 설정도 동작한다.

### 24.5 편집과 피아노롤

- 음표 클릭이 정확한 트랙과 문자열을 선택한다.
- 연결음 클릭이 전체 연결 문자열을 선택한다.
- 빈 위치 클릭이 해당 시간의 편집 위치로 이동한다.
- 다른 트랙은 흐리게 표시되고 숨김 설정이 적용된다.
- 잘못된 MML 입력 중 마지막 정상 피아노롤이 흐리게 유지된다.

### 24.6 저장

- 마지막 프로젝트와 실행 취소 기록이 자동 복원된다.
- `.nyangmml`에는 실행 취소 기록이 포함되지 않는다.
- `.mml`에서 주석과 냥냥 전용 설정이 제거된다.
- 네 가지 MML 가져오기 방식이 기존 트랙을 문서대로 처리한다.
- 프로젝트 제목이 안전한 파일명으로 변환된다.

### 24.7 기존 앱 회귀

- MML이 닫혀 있을 때 기존 건반 레이아웃과 입력 지연이 달라지지 않는다.
- 모바일 멀티터치가 유지된다.
- 한 건반과 두 건반 옥타브 선택이 유지된다.
- 전조, 음색, 서스테인, 전체 음량이 기존대로 동작한다.
- MML 버튼의 불어서 연주 확인창에서 취소와 끄고 열기가 정확히 동작한다.

## 25. 완료 조건

아래 항목을 모두 만족해야 MML 스튜디오 구현이 완료된 것으로 본다.

1. 발바닥 버튼으로 분할 MML 화면을 열고 닫을 수 있다.
2. 오른쪽 절반의 기존 건반을 터치, 마우스, 키보드로 계속 연주할 수 있다.
3. 트랙을 제한 없이 추가·삭제하고 이름, 색상, 음색과 믹서 상태를 바꿀 수 있다.
4. 마비노기 형식 MML을 붙여넣고 트랙별로 편집·재생할 수 있다.
5. 사용자 제공 기준 MML이 파싱되고 재생된다.
6. 피아노롤이 음높이, 길이, 마디, 템포, 박자표와 재생 위치를 표시한다.
7. 피아노롤 음표가 정확한 MML 텍스트 위치로 이동한다.
8. 실시간 녹음과 이어붙이기 녹음이 모두 동작한다.
9. 메트로놈과 녹음 시간 진행이 문서대로 독립 또는 동기화된다.
10. 일반 리듬, 점음표와 셋잇단을 자동 판정한다.
11. 왼쪽·오른쪽 입력을 통합해 연결된 트랙에 화음을 최대한 보존한다.
12. 용량을 넘은 음을 기록하지 않고 경고한다.
13. 수정과 삽입 모드가 기존 트랙을 정해진 범위에서만 변경한다.
14. 전체·구간 반복, 재생, 일시정지와 정지가 남는 음 없이 동작한다.
15. `.mml`과 `.nyangmml` 저장·불러오기 및 네 가지 가져오기 방식이 동작한다.
16. 마지막 프로젝트 자동 저장과 실행 취소·다시 실행이 복원된다.
17. 불어서 연주가 켜진 상태에서는 확인 후 끄거나 MML 진입을 취소할 수 있다.
18. 모바일과 데스크톱에서 화면이 겹치지 않고 가로형 구조를 유지한다.
